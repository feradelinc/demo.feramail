# Backend discrepancy audit

Audited main `1763efde4dfaa8cc6fa3c9485ab083f431aaf2d9`, candidate `0eaca53a7e6bbea79983fde0a7f7428b655dc4bd`, and immutable release 83. Exact source bytes/hashes are bundled in inventory. This audit does not establish authenticated production behavior.

|Finding|Source evidence / consequence|Studio handling / correction|
|---|---|---|
|Owner override|Baseline mutations accept body owner; qualified `authorizeOwner` checks original and selected owner permissions, and preserves signed managed-service identity.|Proxy rejects every differing owner, disallows user-supplied headers and verifies tenant-scoped SMTP/template reads. Existing stronger backend scope is preserved; no broad auth patch is deployed.|
|SMTP password update|Configuration service assigns `item.password = password` on updates, even when omitted.|Editor requires deliberate replacement; omission is rejected. Separate draft PR preserves undefined omission.|
|Stored credentials|Configuration model has a string password column, no visible application encryption/decryption layer. Ordinary GET excludes password.|No claim that source proves credential encryption. Database/storage encryption is a separate infrastructure review; do not confuse it with field encryption. No credential data was inspected.|
|Transport secure preference|Raw transport and Template.send derive secure from 465/2465 and requireTLS from 587/25/2587.|Explain port-derived behavior; local capture uses 1025 only under explicit local sandbox policy. No invented verify endpoint.|
|Template fields overwrite|Updates assign every supported field.|Editor sends all fields and validates JSON/lengths; incomplete advanced requests are refused.|
|Search owner/projection|Search scopes to req.instance and passes attributes; Template.byIndex currently discards attributes.|Owner URL cannot switch tenants. Actual response is shown without claiming field minimization. Separate draft PR forwards attributes.|
|Rendering dependency|Template subject uses text output and body uses static/full XSLT wrapper; support/rendering posts `{xml,xsl}` to associated FeraRender `/api/v1/xml` and reads `data.result`.|Browser XSLT is labeled approximate. Optional fixed Render integration is disabled by default. No send-based preview.|
|Attachments|Raw/template paths pass Nodemailer attachment options, including potentially unsafe path/href inputs if called directly.|Studio permits bounded inline base64 PDF/PNG/JPEG/text only, including CID images, with signature checks. A broad backend file-access switch could break trusted legacy invoice callers; it was not applied. Direct API hardening needs coordinated review.|
|Submission result|Nodemailer info plus optional rendered payload is returned; provider acceptance is not final inbox delivery.|Show actual message IDs/accepted/rejected/provider response. No fabricated open rates, event feed, inbound mailbox, batch or scheduling API.|
|Ambiguous retries|Baseline sends have no universal idempotency contract. Qualified code additionally supports delivery operation IDs/receipts used by managed integrations.|Studio does not repurpose completion bindings and never automatically retries. Matching uncertain payloads require explicit duplicate acknowledgement.|
|Shared-owner provisioner|Absent from main, present in candidate and qualified release; authenticated internal function relates to FeraSign shared email identity.|Read-only documentation only. Proxy rejects it regardless of its authentication mechanism. Its direct service authorization requires separate review.|

Prepared [backend PR #2](https://github.com/feradelinc/feradel.email.api/pull/2), commit `09d6ddab3c7e2524015c20dfc1f42adee3052e55`, contains only password-omission preservation and field-projection forwarding plus regressions. All 28 backend tests pass, including signed legacy invoice delivery. It remains a draft, is not merged, and is not deployed. [Review patch](backend-contract-corrections.patch) is provided; do not apply it over production without its normal release qualification. No Matters API code, production configuration, signing keys, SMTP provider credentials or infrastructure were changed.
